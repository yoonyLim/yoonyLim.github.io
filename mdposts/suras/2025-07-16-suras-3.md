# [SuraS 개발일지 3] Behavior Tree로 적 이동, 추격, 벽 타기 구현하기

## 1. 개요

### 1.1 사전 배경

SuraS의 적 AI에서 가장 오래 붙잡았던 부분은 이동이었다. FPS 게임의 적 이동은 단순히 플레이어에게 `MoveTo`하는 것으로 끝나지 않는다. 플레이어가 빠르게 움직이기 때문에 적은 플레이어 주변을 둘러싸듯 추격해야 하고, 너무 많은 적이 동시에 공격하면 안 되며, 수직 지형을 넘어오지 못하면 플레이어가 높은 곳으로 도망가기만 해도 전투가 끊긴다.

그래서 본인은 적 이동을 다음과 같은 문제로 나누어 구현했다.

1. 적의 상태를 `Passive`, `Chase`, `Pursue`, `Attacking`, `Climbing` 등으로 나눈다.
2. 플레이어 주변의 추격 위치를 토큰 기반으로 나누어 배치한다.
3. 공격 토큰을 사용해 한 번에 공격하는 적 수를 제한한다.
4. 순찰 경로와 전투 추격 경로를 Behavior Tree Task로 분리한다.
5. Smart NavLink와 전용 BT Task를 이용해 벽 타기를 구현한다.

## 3. 적 상태 enum

AI 상태는 `EEnemyStates` enum으로 정의했다. 이 enum은 C++ 코드뿐 아니라 Blackboard enum 값으로도 사용된다.

```cpp
UENUM(BlueprintType)
enum class EEnemyStates : uint8
{
    None UMETA(DisplayName = "None"),
    Passive UMETA(DisplayName = "Passive"),
    Chase UMETA(DisplayName = "Chase"),
    Pursue UMETA(DisplayName = "Pursue"),
    Attacking UMETA(DisplayName = "Attacking"),
    Climbing UMETA(DisplayName = "Climbing"),
    CoopAttacking UMETA(DisplayName = "CoopAttacking"),
    Traverse UMETA(DisplayName = "Traverse"),
    Dead UMETA(DisplayName = "Dead")
};
```

이 상태들은 각각 다음 의미로 사용했다.

| 상태 | 의미 |
| :---: | --- |
| `Passive` | 아직 플레이어와 전투하지 않는 기본 상태 |
| `Chase` | 플레이어를 발견했지만 추격 토큰을 받지 못해 일반 추격 |
| `Pursue` | 플레이어 주변의 특정 위치를 예약해 적극 추격 |
| `Attacking` | 공격 가능한 상태 |
| `Climbing` | 벽을 타는 중 |
| `CoopAttacking` | 다른 적과 협동 공격 중 |

처음에는 상태가 많아지는 것이 오히려 복잡해 보였지만, 결과적으로는 상태를 나눈 덕분에 "벽 타는 중에는 Perception으로 추격 상태를 덮어쓰지 않기", "협동 공격 중에는 일반 AI를 멈추기" 같은 예외 처리를 명확히 할 수 있었다.

## 4. 공격 토큰과 추격 토큰

많은 적이 한 번에 플레이어를 향해 달려들면 전투가 불공정해진다. 또한 모든 적이 플레이어의 정확한 위치로 `MoveTo`하면 적들이 한 점에 뭉쳐 서로 밀거나 겹치는 문제가 생긴다. 이를 해결하기 위해 플레이어에게 토큰 컴포넌트를 두었다.

```cpp
bool UACPlayerAttackTokens::ReserveAttackToken(int ReserveAmount)
{
    if (_EnemyAttackTokens >= ReserveAmount)
    {
        _EnemyAttackTokens -= ReserveAmount;
        return true;
    }

    return false;
}

int UACPlayerAttackTokens::ReservePursuitToken(int ReserveAmount)
{
    if (_EnemyPursuitTokens >= ReserveAmount)
    {
        _EnemyPursuitTokens -= ReserveAmount;
        return _EnemyPursuitTokens;
    }

    return -1;
}
```

공격 토큰은 동시에 공격 가능한 적의 수를 제한하고, 추격 토큰은 플레이어 주변에서 적이 차지할 위치 인덱스를 정한다. 이를 통해 적들이 플레이어 주변을 둘러싸듯 배치되도록 했다.

AI Controller에서는 플레이어를 발견했을 때 먼저 Pursuit Token을 예약한다.

```cpp
void AEnemyBaseAIController::SetStateToChaseOrPursue(AActor* TargetActor)
{
    if (GetCurrentState() != EEnemyStates::Pursue && GetCurrentState() != EEnemyStates::Attacking)
    {
        if (ASuraPawnPlayer* const Player = Cast<ASuraPawnPlayer>(TargetActor))
        {
            GetBlackboardComponent()->SetValueAsObject("AttackTarget", Player);

            int PursuitIndex = Player->GetAttackTokensComponent()->ReservePursuitToken(1);

            if (PursuitIndex != -1)
            {
                PursuitIndex = Player->GetAttackTokensComponent()->GetMaxEnemyPursuitTokens() - PursuitIndex - 1;
                GetBlackboardComponent()->SetValueAsInt("PursuitIndex", PursuitIndex);
                UpdateCurrentState(EEnemyStates::Pursue);
            }
            else
            {
                UpdateCurrentState(EEnemyStates::Chase);
            }
        }
    }
}
```

토큰을 받은 적은 `Pursue`, 받지 못한 적은 `Chase` 상태가 된다. 이 차이를 둔 덕분에 모든 적이 동시에 최적 공격 위치를 차지하려 하지 않고, 일부 적만 적극적으로 접근한다.

## 5. 추격 위치 계산

Pursue 상태의 핵심은 플레이어 주변의 어느 지점으로 갈 것인지 계산하는 것이다. `BTT_FindPursuitPoint`는 플레이어 주변 360도를 추격 토큰 개수만큼 나누고, `PursuitIndex`에 해당하는 위치를 Blackboard의 `TargetLocation`에 저장한다.

```cpp
float AngleBetween = 360.f / Player->GetAttackTokensComponent()->GetMaxEnemyPursuitTokens();

float AngleRadians = FMath::DegreesToRadians(PursuitIndex * AngleBetween);
float AttackRadius = OwnerComp.GetBlackboardComponent()->GetValueAsFloat("AttackRadius");

float PosX = TargetActorLocation.X + AttackRadius * FMath::Cos(AngleRadians);
float PosY = TargetActorLocation.Y + AttackRadius * FMath::Sin(AngleRadians);
float PosZ = TargetActorLocation.Z;

OwnerComp.GetBlackboardComponent()->SetValueAsVector("TargetLocation", FVector(PosX, PosY, PosZ));
```

이 방식은 원형 배치를 아주 단순한 수학으로 구현한다. 예를 들어 추격 토큰이 8개라면 각 적은 45도 간격으로 플레이어 주변 위치를 배정받는다. 하이퍼 FPS처럼 플레이어가 계속 움직이는 게임에서는 이 TargetLocation도 계속 갱신되므로, 적들이 플레이어를 중심으로 재배치되는 느낌을 줄 수 있다.

## 6. 순찰 Task

전투 상태가 아닐 때는 Patrol Route를 따라 이동하도록 했다. `BTT_Patrol`은 Enemy가 가지고 있는 Patrol Route에서 현재 인덱스의 위치를 꺼내 Blackboard에 저장하고, 이후 인덱스를 증가시킨다.

```cpp
EBTNodeResult::Type UBTT_Patrol::ExecuteTask(UBehaviorTreeComponent& OwnerComp, uint8* NodeMemory)
{
    if (ASuraCharacterEnemyBase* const Enemy = Cast<ASuraCharacterEnemyBase>(OwnerComp.GetAIOwner()->GetCharacter()))
    {
        if (!Enemy->GetPatrolRoute())
            return EBTNodeResult::Failed;

        FVector TargetLocation = Enemy->GetPatrolRoute()->GetCurrentPatrolIndexPosition();
        OwnerComp.GetBlackboardComponent()->SetValueAsVector("TargetLocation", TargetLocation);
        Enemy->GetPatrolRoute()->IncrementPatrolRoute();

        FinishLatentTask(OwnerComp, EBTNodeResult::Succeeded);
        return EBTNodeResult::Succeeded;
    }

    return EBTNodeResult::Failed;
}
```

순찰 자체는 단순하지만 Behavior Tree의 상태와 연결하면 의미가 생긴다. 평소에는 Patrol Route를 돌다가 플레이어를 보면 Chase/Pursue로 전환되고, 피격당해도 전투 상태로 전환된다.

## 7. Strafe 이동

적이 플레이어에게 직선으로만 달려오면 전투가 매우 단조로워진다. 그래서 짧은 시간 동안 좌우로 움직이는 Strafe Task를 추가했다.

```cpp
if (FMath::RandRange(0, 1))
    Mem->StrafeDirection = 1;
else
    Mem->StrafeDirection = -1;

StrafeDuration += FMath::RandRange(-StrafeDurationDeviation, StrafeDurationDeviation);
```

Tick에서는 적의 오른쪽 벡터 방향으로 이동 입력을 준다.

```cpp
if (ASuraCharacterEnemyBase* const Enemy = Cast<ASuraCharacterEnemyBase>(OwnerComp.GetAIOwner()->GetCharacter()))
    Enemy->AddMovementInput(Mem->StrafeDirection * Enemy->GetActorRightVector(), 0.2f);
```

이 Task 자체는 작지만, 원거리 적이나 근접 적이 플레이어 주변에서 계속 미세하게 위치를 바꾸는 데 사용될 수 있다.

## 8. 벽 타기: Smart NavLink

SuraS의 적 AI에서 가장 어려웠던 부분 중 하나는 벽을 타는 적 이동이었다. UE의 기본 NavMesh만으로는 벽을 기어오르는 동작을 자연스럽게 처리하기 어렵기 때문에 `AEnemyClimbNavLink`를 만들고 Smart Link에 도착했을 때 적 상태를 `Climbing`으로 바꾸었다.

```cpp
void AEnemyClimbNavLink::OnReceiveSmartLinkReached(AActor* Agent, const FVector& Destination)
{
    if (Destination.Z < Agent->GetActorLocation().Z)
        return;

    if (ASuraCharacterEnemyBase* Enemy = Cast<ASuraCharacterEnemyBase>(Agent))
    {
        CachedEnemy = Enemy;
        CachedEnemy->GetDamageSystemComp()->OnDeath.AddUObject(this, &AEnemyClimbNavLink::OnCachedEnemyDeath);

        CachedEnemy->GetAIController()->ClearFocus(EAIFocusPriority::Gameplay);

        if (CachedEnemy->GetAIController()->GetCurrentState() == EEnemyStates::Pursue ||
            CachedEnemy->GetAIController()->GetCurrentState() == EEnemyStates::Attacking)
        {
            CachedEnemy->GetAIController()->EndPursueState();
        }

        CachedEnemy->GetMovementComponent()->StopMovementImmediately();
        CachedEnemy->GetAIController()->UpdateCurrentState(EEnemyStates::Climbing);
        CachedEnemy->GetAIController()->GetBlackboardComponent()->SetValueAsVector("TargetLocation", Destination);
    }
}
```

여기서 신경 쓴 부분은 적이 벽을 타기 시작할 때 기존 추격 토큰을 반환하고, Focus를 제거하며, 이동을 즉시 멈추는 것이다. 그렇지 않으면 NavLink에 도착한 순간에도 기존 MoveTo나 Focus가 살아 있어 적이 벽을 타는 방향이 틀어질 수 있다.

## 9. 벽 타기: Behavior Tree Task

실제 벽 타기 이동은 `BTT_Climb`에서 수행된다. 처음에는 적의 Movement Mode를 `MOVE_Flying`으로 바꾼 뒤 등반 몽타주를 재생한다.

```cpp
UAnimMontage* ClimbAnimation = Enemy->GetClimbMontage();
Enemy->PlayAnimMontage(ClimbAnimation);

Enemy->GetCharacterMovement()->SetMovementMode(MOVE_Flying);

Mem->bHasLedgeDetected = false;
Mem->bIsDoneClimbing = false;

FRotator Rotation = OwnerComp.GetBlackboardComponent()->GetValueAsRotator("TargetRotation");
Enemy->SetActorRotation(Rotation);
```

Tick에서는 계속 벽과 지면을 Trace하여 지금 적이 벽 앞에 있는지, 턱에 도달했는지, 올라갈 바닥이 있는지 판단한다.

```cpp
bool bIsWallAhead = GetWorld()->SweepSingleByChannel(
    WallHit,
    Mem->CachedEnemy.Get()->GetActorLocation(),
    ClimbLedgeSweepEnd,
    Mem->CachedEnemy.Get()->GetActorQuat(),
    WALL_TRACE_CHANNEL,
    Mem->CachedEnemy.Get()->GetCapsuleComponent()->GetCollisionShape(),
    ClimbLedgeParams,
    ClimbResponseParams
);
```

벽이 감지되면 위쪽에서 다시 Sweep하여 올라갈 수 있는 ledge floor가 있는지 확인한다.

```cpp
if (bLedgeFloorHit && WallHit.IsValidBlockingHit() &&
    WallHit.ImpactNormal.Z >= FMath::Cos(FMath::DegreesToRadians(50.f)))
{
    Mem->bHasLedgeDetected = true;
    MoveUpTheLedge(NodeMemory, WallHit.ImpactNormal);
}
else
{
    Mem->TargetVelocity = Mem->CachedEnemy.Get()->GetActorUpVector() * 600.f;
}
```

아직 ledge를 찾지 못했다면 위로 올라가고, ledge를 찾으면 벽면의 normal을 이용해 이동 방향을 보정한다.

```cpp
FVector LedgeFloorSlope =
    FVector::VectorPlaneProject(Mem->CachedEnemy.Get()->GetActorForwardVector(), ImpactNormal).GetSafeNormal();

Mem->TargetVelocity = LedgeFloorSlope * 600.f;
```

마지막으로 등반이 끝나면 Movement Mode를 다시 `MOVE_Walking`으로 돌리고, 다시 플레이어를 추격하도록 상태를 전환한다.

```cpp
if (Mem->bIsDoneClimbing)
{
    Mem->CachedEnemy.Get()->StopAnimMontage();
    Mem->CachedEnemy.Get()->GetCharacterMovement()->SetMovementMode(MOVE_Walking);
    Mem->CachedEnemy.Get()->SetActorRotation(
        Mem->CachedEnemy.Get()->GetAIController()->GetBlackboardComponent()->GetValueAsRotator("TargetRotation")
    );
    Mem->CachedEnemy.Get()->GetAIController()->SetStateToChaseOrPursue(
        Mem->CachedEnemy.Get()->GetAIController()->GetAttackTarget()
    );
    FinishLatentTask(OwnerComp, EBTNodeResult::Succeeded);
}
```

이 로직은 개발 중 가장 많이 고친 부분 중 하나였다. 적이 벽을 타다가 죽는 경우, ledge를 감지하지 못하는 경우, 올라간 뒤 회전이 틀어지는 경우, 추격 토큰이 반환되지 않는 경우가 계속 발생했기 때문이다.

## 10. 점프 NavLink

벽 타기와 별개로 점프 링크도 구현했다. 위로 이동해야 하는 NavLink에 도착하면 `JumpWall`을 호출하고, 캐릭터의 LaunchVelocity를 계산해 포물선으로 이동하게 했다.

```cpp
void AEnemyJumpNavLink::OnReceiveSmartLinkReached(AActor* Agent, const FVector& Destination)
{
    if (Destination.Z < Agent->GetActorLocation().Z)
        return;

    if (ASuraCharacterEnemyBase* Enemy = Cast<ASuraCharacterEnemyBase>(Agent))
    {
        Enemy->JumpWall(Destination);
    }
}
```

`JumpWall`에서는 UE의 `SuggestProjectileVelocity_CustomArc`를 사용했다.

```cpp
UGameplayStatics::SuggestProjectileVelocity_CustomArc(
    this,
    LaunchVelocity,
    GetActorLocation(),
    FinalDestination
);

LaunchCharacter(LaunchVelocity, true, true);
```

벽 타기는 벽면을 따라 기어오르는 느낌, 점프 링크는 수직 단차를 한 번에 넘는 느낌을 주기 위해 구분했다.

## 11. 후기

이번 AI 이동 작업을 하며 느낀 것은 "이동"이 단순한 좌표 계산이 아니라 전투 디자인 그 자체라는 점이었다. 플레이어 주변의 어느 위치를 차지할지, 몇 마리가 동시에 공격할지, 높은 지형을 어떻게 따라올지에 따라 게임의 체감 난이도가 크게 달라졌다.

특히 벽 타기는 구현 과정에서 가장 시행착오가 많았다. 단순히 `MOVE_Flying`으로 바꾸고 위로 올리면 될 것 같지만 실제로는 회전, 충돌, ledge 감지, 사망 처리, 추격 상태 복구까지 모두 연결해야 했다. 그래도 이 기능 덕분에 SuraS의 적들은 평면적인 FPS 적보다 훨씬 적극적으로 플레이어를 압박할 수 있었다.
