# [SuraS 개발일지 1] UE5 하이퍼 FPS 프로젝트 구조 잡기

## 1. 개요

### 1.1 사전 배경

SuraS는 Unreal Engine 5로 제작한 하이퍼 FPS 프로젝트이다. 본 프로젝트에서 본인이 주로 맡은 부분은 적 AI와 전투 시스템이었다. 특히 적들이 단순히 플레이어를 향해 달려오는 것이 아니라 Behavior Tree를 기반으로 상태를 바꾸고, 지형을 타고 오르며, 서로를 던져 공격하는 식의 전투 패턴을 구현하는 것이 핵심이었다.

이번 개발일지 시리즈는 전체 팀 커밋을 그대로 나열하기보다 본인의 GitHub 계정으로 작성된 커밋만을 골라 개발 과정을 정리한다. 기준으로 사용한 author 정보는 아래와 같다.

```text
Hayoon Lim / 임하윤 <64838255+yoonyLim@users.noreply.github.com>
```

따라서 Azure DevOps의 PR merge commit이나 다른 팀원들의 커밋은 개발 흐름을 이해하기 위한 배경으로만 참고하고, 본문에서 선택한 주요 커밋 목록에는 포함하지 않았다.

### 1.2 수행 요약

첫 단계에서는 UE5 First Person Template 기반의 프로젝트를 SuraS 전용 구조로 바꾸었다. 이후 적 AI 개발을 위해 필요한 C++ 폴더 구조, 캐릭터 상속 구조, ActorComponent 기반의 시스템 구조를 미리 잡아두었다.

## 3. UE5 템플릿에서 프로젝트로

프로젝트의 첫 커밋은 UE5 First Person Template을 기반으로 만들어졌다. 따라서 초기에는 `FirstPerson`, `FPWeapon`, `StarterContent`, `SuraSProjectile`, `SuraSWeaponComponent` 같은 템플릿 기반 파일이 존재했다.

그러나 SuraS는 단순한 FPS 습작이 아니라 적 AI와 빠른 이동 전투를 중심으로 한 팀 프로젝트였기 때문에 템플릿 구조 그대로는 한계가 있었다. 특히 UE 프로젝트는 C++ 코드만큼이나 `.uasset` 파일이 많아지기 때문에 초기에 Content 폴더를 정리하지 않으면 나중에 기능 단위로 파일을 찾기 매우 어려워진다.

그래서 다음과 같은 Content 폴더 기준을 먼저 잡았다.

| 폴더 | 용도 |
| :---: | --- |
| `Content/Animations` | 적, 플레이어, 공격 몽타주 등 애니메이션 리소스 |
| `Content/Blueprints` | 캐릭터, AI, 유틸리티, 트리거 박스 등 블루프린트 |
| `Content/Effects` | Niagara, 이펙트성 리소스 |
| `Content/GameAttributes` | DataTable, Curve 등 수치 조정용 데이터 |
| `Content/Scenes` | 테스트 맵 및 개발용 맵 |
| `Content/UI` | 체력바, 피격 UI, 영상 위젯 등 |

UE 프로젝트에서는 이런 폴더 정리가 단순한 미관 문제가 아니다. 적 AI 개발 중에는 Behavior Tree, Blackboard, Animation Blueprint, DataTable, C++ Task가 함께 움직이므로 파일이 기능별로 묶여 있어야 디버깅과 협업이 가능하다.

## 4. C++ 파일 구조

초기 C++ 구조에서 가장 중요했던 부분은 템플릿 클래스와 SuraS 전용 클래스를 분리하는 것이었다. `ff1bcb843` 커밋에서 플레이어와 적 캐릭터, ActorComponent, 속성 데이터 구조가 추가되었다.

초기 구조는 대략 다음과 같은 방향으로 잡았다.

```text
Source/SuraS/Private/ActorComponents
Source/SuraS/Private/Characters
Source/SuraS/Private/Characters/Enemies
Source/SuraS/Private/Characters/Player
Source/SuraS/Public/GameAttributes
```

이때부터 이미 적 시스템은 하나의 거대한 캐릭터 클래스에 모든 기능을 넣는 방식이 아니라, 역할에 따라 나누어 확장할 수 있는 방식으로 설계하려 했다.

예를 들어 이후 개발에서는 아래와 같은 파일들이 추가되었다.

```text
Source/SuraS/Private/Characters/Enemies/AI/EnemyBaseAIController.cpp
Source/SuraS/Private/Characters/Enemies/AI/Tasks/Movements/BTT_Patrol.cpp
Source/SuraS/Private/Characters/Enemies/AI/Tasks/Movements/BTT_Climb.cpp
Source/SuraS/Private/Characters/Enemies/AI/Tasks/Attacks/BTT_CoopAttack.cpp
Source/SuraS/Private/Utilities/EnemyClimbNavLink.cpp
Source/SuraS/Private/Utilities/EnemyCoopAttackTriggerBox.cpp
```

즉, 초반 구조 정리는 후반의 적 AI 작업을 위해 필요한 기반 작업이었다.

## 5. 설계 방향

SuraS에서 적은 단순히 "플레이어를 발견하면 MoveTo"만 수행하는 존재가 아니어야 했다. 하이퍼 FPS에서는 플레이어가 빠르게 이동하고, 점프와 대시를 반복하며, 전투 공간을 넓게 사용한다. 따라서 적 AI도 다음과 같은 요구를 만족해야 했다.

1. 플레이어를 감지하면 상태를 전환해야 한다.
2. 플레이어 주변에 여러 적이 한꺼번에 겹치지 않도록 해야 한다.
3. 공격 가능한 적의 수를 제한해 전투가 불공정해지지 않도록 해야 한다.
4. 수직 지형을 오르거나 점프 링크를 타고 이동해야 한다.
5. 특정 트리거 안에서는 서로를 던지는 협동 공격을 수행해야 한다.

이 요구사항들을 구현하기 위해 이후 개발에서는 Behavior Tree, Blackboard, AI Perception, NavLink, Animation Notify State, Motion Warping, DataTable을 함께 사용했다.

## 6. 후기

이 시기의 작업은 겉보기에는 프로젝트 폴더를 만들고 파일을 정리하는 일에 가깝다. 그러나 개인적으로는 이 단계가 가장 중요했다고 생각한다. UE5 프로젝트는 초반에 구조를 잡지 않으면 후반에 블루프린트와 C++이 서로 뒤엉켜 디버깅이 매우 어려워진다.

이후 포스트부터는 본격적으로 본인이 맡았던 적 AI, Behavior Tree, 벽 타기, 추격 포지션 계산, 적 협동 공격 구현 과정을 코드와 함께 정리한다.
