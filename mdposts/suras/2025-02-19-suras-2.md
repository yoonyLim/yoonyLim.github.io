# [SuraS 개발일지 2] Damage System과 Behavior Tree 기반 적 AI의 시작

## 1. 개요

### 1.1 사전 배경

FPS 게임에서 적 AI를 만들 때 가장 먼저 필요한 것은 "적이 어떻게 움직이는가"가 아니라 "적이 어떤 상태를 가지고, 어떻게 전투 루프 안으로 들어오는가"이다. 아무리 이동 로직을 잘 만들어도 적이 데미지를 받았을 때 상태가 바뀌지 않거나, 공격 중 사망했을 때 Behavior Tree가 멈추지 않으면 전투 시스템 전체가 불안정해진다.

따라서 본인은 적 AI의 시작점을 Damage System과 Behavior Tree 연결로 잡았다. 적이 데미지를 받고, 체력바를 띄우고, 플레이어를 추격하고, 공격 몽타주를 실행하는 최소 전투 루프를 먼저 구현했다.

### 1.2 수행 요약

이번 단계에서는 다음 내용을 구현했다.

1. 적에게 적용할 Damage System Component
2. `Damageable` 인터페이스
3. 적 체력바 UI
4. Enemy Base AI Controller
5. Behavior Tree와 Blackboard 연결
6. 근접 적, 원거리 적의 첫 공격 루프

## 3. Damage System

가장 먼저 만든 핵심 구조는 Damage System이다. 이 시스템은 적의 체력, 부위 체력, 피격, 사망 이벤트를 관리하는 역할을 한다. 실제 최종 코드에서는 `ASuraCharacterEnemyBase`가 `UACEnemyDamageSystem`을 Component로 소유한다.

```cpp
ASuraCharacterEnemyBase::ASuraCharacterEnemyBase()
{
    DamageSystemComp = CreateDefaultSubobject<UACEnemyDamageSystem>(TEXT("DamageSystemComponent"));
    AddOwnedComponent(DamageSystemComp);

    HealthBarWidget = CreateDefaultSubobject<UWidgetComponent>(TEXT("HealthBar"));
    MotionWarpingComponent = CreateDefaultSubobject<UMotionWarpingComponent>(TEXT("MotionWarping"));

    bUseControllerRotationYaw = true;
    GetCharacterMovement()->bUseRVOAvoidance = true;
    GetCharacterMovement()->GravityScale = 2.f;
}
```

여기서 중요한 점은 `DamageSystemComp`만 추가한 것이 아니라 `MotionWarpingComponent`, `HealthBarWidget`, `RVOAvoidance` 같은 이후 AI 전투에 필요한 요소들도 적 Base에 함께 들어갔다는 것이다. 이후 협동 공격에서 Motion Warping을 사용하고, 전투 중 적들이 서로 밀집하는 현상을 줄이기 위해 RVO를 켜는 구조가 여기서 시작된다.

## 4. 적 초기화와 DataTable

적의 수치를 코드에 고정하지 않고 DataTable에서 읽어오도록 했다. 적 타입마다 체력, 공격력, 이동 속도, 공격 애니메이션, 피격 애니메이션, 등반 애니메이션 등을 다르게 줄 수 있어야 했기 때문이다.

```cpp
if (const auto EnemyAttributesData = EnemyAttributesDT.DataTable->FindRow<FEnemyAttributesData>(EnemyType, ""))
{
    GetDamageSystemComp()->SetMaxHealth(EnemyAttributesData->MaxHealth);
    GetDamageSystemComp()->SetHealth(EnemyAttributesData->MaxHealth);

    GetCharacterMovement()->MaxWalkSpeed = EnemyAttributesData->MaxWalkSpeed;

    AttackDamageAmount = EnemyAttributesData->AttackDamageAmount;
    AttackRate = EnemyAttributesData->AttackRate;
    MeleeAttackRange = EnemyAttributesData->MeleeAttackRange;

    HitAnimations = EnemyAttributesData->HitAnimations;
    DeathAnimations = EnemyAttributesData->DeathAnimations;
    AttackAnimations = EnemyAttributesData->AttackAnimations;
    ClimbAnimation = EnemyAttributesData->ClimbAnimation;
    ThrowAnimation = EnemyAttributesData->ThrowAnimation;
    FallingAnimation = EnemyAttributesData->FallingAnimation;
}
```

이 구조 덕분에 이후 `Melee`, `Rifle`, `Bombard`, `Charger`, `Turret`처럼 적 종류가 늘어나도 C++ 코드를 매번 새로 고치기보다 DataTable과 Blueprint에서 수치를 조정할 수 있었다.

## 5. AI Controller와 Blackboard 초기화

적 AI는 `AEnemyBaseAIController`가 Behavior Tree와 Blackboard를 실행하는 방식으로 구성했다. 적이 possession될 때 적이 가진 Behavior Tree를 가져와 Blackboard를 사용하고, DataTable에서 읽은 값을 Blackboard에 넣는다.

```cpp
void AEnemyBaseAIController::OnPossess(APawn* PossessedPawn)
{
    Super::OnPossess(PossessedPawn);

    if (ASuraCharacterEnemyBase* Enemy = Cast<ASuraCharacterEnemyBase>(PossessedPawn))
    {
        CachedPossessedPawn = Enemy;

        if (UBehaviorTree* const BehaviorTree = Enemy->GetBehaviorTree())
        {
            UBlackboardComponent* Bboard;
            UseBlackboard(BehaviorTree->BlackboardAsset, Bboard);
            Blackboard = Bboard;

            if (const auto EnemyAttributesData = Enemy->EnemyAttributesDT.DataTable->FindRow<FEnemyAttributesData>(Enemy->GetEnemyType(), ""))
            {
                InitializeBlackBoard(
                    EnemyAttributesData->StrafeRadius,
                    EnemyAttributesData->ChaseStrafeRadius,
                    EnemyAttributesData->AttackRadius,
                    EnemyAttributesData->AttackRate
                );
            }

            RunBehaviorTree(BehaviorTree);
            UpdateCurrentState(EEnemyStates::Passive);
            Enemy->SetUpAIController(this);
        }
    }
}
```

Blackboard에 넣은 값은 이후 Behavior Tree Task들이 공유한다. 예를 들어 `AttackRadius`는 추격 포지션 계산에 사용하고, `AttackRate`는 공격 루프 조절에 사용한다.

## 6. Perception과 상태 전환

적이 플레이어를 시야로 감지하면 바로 공격하는 것이 아니라 `Chase` 혹은 `Pursue` 상태로 들어가도록 했다.

```cpp
void AEnemyBaseAIController::OnTargetSighted(AActor* SeenTarget, FAIStimulus const Stimulus)
{
    if (GetCurrentState() != EEnemyStates::Climbing && GetCurrentState() != EEnemyStates::CoopAttacking)
        SetStateToChaseOrPursue(SeenTarget);
}
```

여기서 `Climbing`, `CoopAttacking` 상태를 제외한 이유는 벽을 타는 중이거나 협동 공격 중일 때 시야 감지로 상태가 덮어씌워지면 애니메이션과 이동이 깨지기 때문이다. UE Behavior Tree는 상태 전환이 쉬운 만큼, 상태를 바꾸면 안 되는 순간을 명확히 막아야 한다.

## 7. 피격 후 추격으로 전환

플레이어가 적을 먼저 공격했을 때도 적은 전투 상태로 들어가야 한다. 이를 위해 `OnHitEnded`에서 현재 상태가 추격이나 공격, 등반이 아닐 때만 플레이어를 향해 상태를 바꾼다.

```cpp
void ASuraCharacterEnemyBase::OnHitEnded(UAnimMontage* AnimMontage, bool bInterrupted)
{
    ASuraPawnPlayer* Player = Cast<ASuraPawnPlayer>(GetPlayerController()->GetPawn());

    if (Player &&
        AIController->GetCurrentState() != EEnemyStates::Pursue &&
        AIController->GetCurrentState() != EEnemyStates::Attacking &&
        AIController->GetCurrentState() != EEnemyStates::Climbing)
    {
        GetAIController()->SetStateToChaseOrPursue(Player);
    }
}
```

이 처리를 넣기 전에는 플레이어가 적을 때려도 적이 전투 상태로 자연스럽게 전환되지 않거나, 피격 애니메이션 중 상태가 꼬일 가능성이 있었다.

## 8. 근접 공격과 원거리 공격의 분리

근접 적은 `BTT_MeleeAttack`, 원거리 적은 `BTT_Fire`를 통해 공격하도록 분리했다. 여기서 중요한 점은 공격 판정 자체를 단순 Tick 로직으로 처리하지 않고, Animation Montage와 Notify State를 활용했다는 것이다.

근접 공격의 경우 공격 몽타주 중 실제 타격 프레임에 Notify State를 배치하여 플레이어에게 데미지를 주는 방식으로 구성했다. 원거리 적은 발사 몽타주와 총기/투사체 클래스를 연결하여 `SuraCharacterEnemyRifle`, `SuraFirearmRifle`, `SuraEnemyProjectile` 흐름으로 분리했다.

이 방식의 장점은 다음과 같다.

1. 공격 타이밍이 애니메이션과 맞는다.
2. 적 종류별로 몽타주만 바꿔도 공격 표현을 조정할 수 있다.
3. Behavior Tree는 "공격을 시작한다"는 의사결정만 담당하고, 실제 타격 순간은 애니메이션 시스템이 담당한다.

## 9. 후기

이번 단계에서 만든 것은 아직 복잡한 AI라기보다 적 AI의 기본 골격이다. 그러나 Damage System, Health Bar, AI Controller, Behavior Tree, Blackboard, Animation Notify가 연결되면서 이후의 모든 적 행동을 올릴 수 있는 기반이 만들어졌다.

특히 이후 포스트에서 다룰 추격 토큰, 벽 타기, 협동 공격 모두 이 구조 위에서 구현되었다. 처음부터 "적은 상태를 가진다"는 전제를 두었기 때문에 기능이 늘어났을 때도 단순 분기문이 아니라 Behavior Tree Task와 상태 enum으로 확장할 수 있었다.
