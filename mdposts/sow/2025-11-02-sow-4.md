# [SOW 개발일지 4] 도발, 태그 기반 버프, 웨이브 난이도

## 1. 개요

### 1.1 사전 배경

초기 적 AI가 Core Rune을 향해 이동하고 공격하는 데 집중했다면, 이후 작업은 적의 상태와 웨이브 난이도를 더 세밀하게 제어하는 방향으로 진행되었다. 모든 적이 같은 방식으로 이동하고 같은 방식으로 피해를 받으면 웨이브는 금방 단조로워진다. SOW에서는 도발, 은신, 원거리 저항, 근거리 저항, 웨이브 버프 같은 상태가 필요했다.

이 시기의 핵심은 Behavior Tree의 상태 전환과 Gameplay Tag 기반 상태 표현을 함께 사용하는 것이었다. AI Controller는 현재 상태를 Blackboard에 기록하고, GAS 쪽에서는 Gameplay Tag로 버프와 디버프를 표현한다.

### 1.2 수행 요약

도발 기능을 추가해 특정 대상에게 공격 목표를 강제로 바꿀 수 있게 했고, 일정 시간이 지나면 기존 목표로 복귀하도록 했다. 또한 적 상태 태그를 확장해 은신, 저항, 웨이브 버프를 표현했다. 웨이브 후반에는 터렛 수 제한과 적 버프, 스테이지별 Wave Data 조정이 함께 들어가면서 난이도 조절의 기준이 더 명확해졌다.

## 3. 적 상태 enum과 Blackboard

SOW의 적 상태는 `EEnemyStates` enum으로 정의되어 Behavior Tree와 Blackboard에서 사용된다.

```cpp
UENUM(BlueprintType)
enum class EEnemyStates : uint8
{
    None UMETA(DisplayName = "None"),
    Passive UMETA(DisplayName = "Passive"),
    Attacking UMETA(DisplayName = "Attacking"),
    FollowingIncomingRoute UMETA(DisplayName = "FollowingIncomingRoute"),
    Taunted UMETA(DisplayName = "Taunted"),
    Dead UMETA(DisplayName = "Dead")
};
```

AI Controller는 상태가 바뀔 때마다 Blackboard의 `State` 값을 갱신한다.

```cpp
void AEnemyBaseAIController::UpdateCurrentState(EEnemyStates NewState)
{
    MCurrentState = NewState;
    GetBlackboardComponent()->SetValueAsEnum(
        "State",
        static_cast<uint8>(MCurrentState)
    );
}
```

이 구조를 사용하면 Behavior Tree Decorator나 Task가 적의 현재 상태를 기준으로 분기할 수 있다. 예를 들어 경로 이동 중이면 Route Task를 수행하고, 끝에 도착하면 공격 상태로 전환한다. 도발 상태에서는 기존 목표 대신 도발한 Actor를 공격 대상으로 삼는다.

## 4. 도발 시스템

도발은 적 AI에서 매우 좋은 테스트 케이스였다. 도발은 단순히 목표를 바꾸는 것이 아니라, 기존 목표를 기억했다가 일정 시간이 지난 뒤 복구해야 한다. 또한 도발 중에는 다른 타겟 우선순위 로직이 함부로 목표를 덮어쓰면 안 된다.

```cpp
void AEnemyBaseAIController::Taunt(AActor* TargetActor, float Duration)
{
    CachedAttackTarget = Cast<AActor>(
        GetBlackboardComponent()->GetValueAsObject("AttackTarget")
    );

    bIsTaunted = true;
    GetBlackboardComponent()->SetValueAsObject("AttackTarget", TargetActor);
    UpdateCurrentState(EEnemyStates::Taunted);

    GetWorldTimerManager().SetTimer(
        ResetTauntHandle,
        FTimerDelegate::CreateLambda([&]()
        {
            bIsTaunted = false;
            GetBlackboardComponent()->SetValueAsObject(
                "AttackTarget",
                CachedAttackTarget.Get()
            );
            UpdateCurrentState(EEnemyStates::FollowingIncomingRoute);
        }),
        Duration,
        false
    );
}
```

도발을 만들면서 상태 복구가 특히 중요했다. 도발이 끝난 뒤 적이 계속 도발 대상을 쫓거나, 공격 대상이 null이 되거나, 웨이브 경로로 복귀하지 못하면 전투 흐름이 깨진다. `CachedAttackTarget`과 Timer를 둔 이유는 이 복구 흐름을 명시하기 위해서였다.

## 5. Route 이동에서 공격 상태로 전환

웨이브 적은 경로를 따라가다가 끝에 도착하면 공격 상태가 된다. 직접 이동형 Task에서는 현재 Spline Point를 바라보고 전방 입력을 넣는 방식으로 이동한다.

```cpp
if (Enemy->GetEnemyIncomingRouteComponent()->HasReachedEnd())
{
    Enemy->GetAIController()->UpdateCurrentState(EEnemyStates::Attacking);
    FinishLatentTask(OwnerComp, EBTNodeResult::Succeeded);
    return EBTNodeResult::Succeeded;
}

FVector TargetLocation =
    Enemy->GetEnemyIncomingRouteComponent()->GetCurrentIndexPosition();

if (FVector::Dist(TargetLocation, Enemy->GetActorLocation()) <= 5.f)
{
    Enemy->GetEnemyIncomingRouteComponent()->IncrementIncomingRouteIndex();
}

FVector DirectionVec = (TargetLocation - Enemy->GetActorLocation()).GetSafeNormal();
FRotator DirectionRot = DirectionVec.Rotation();

Enemy->SetActorRotation(FRotator(0.f, DirectionRot.Yaw, 0.f));
Enemy->AddMovementInput(Enemy->GetActorForwardVector(), 1.f);
```

이 Task의 장점은 명확하다. AI MoveTo처럼 경로 탐색 결과를 기다리는 대신, 이미 만들어진 Spline Route를 기준으로 적을 계속 전진시킬 수 있다. 웨이브 적이 많을 때는 이렇게 단순하고 예측 가능한 이동이 더 안정적인 경우가 있었다.

## 6. Gameplay Tag로 표현한 적 상태

SOW는 Gameplay Ability System을 사용하기 때문에, 적의 버프와 디버프 상태를 Gameplay Tag로 표현할 수 있었다. 내가 작업한 태그 중 웨이브와 적 AI에 직접 연결되는 예시는 아래와 같다.

```cpp
UE_DECLARE_GAMEPLAY_TAG_EXTERN(Enemy_Status_Buff_WaveBuff);
UE_DECLARE_GAMEPLAY_TAG_EXTERN(Enemy_Status_Buff_Stealth);
UE_DECLARE_GAMEPLAY_TAG_EXTERN(Enemy_Status_Buff_RangedResistance);
UE_DECLARE_GAMEPLAY_TAG_EXTERN(Enemy_Status_Buff_MeleeResistance);
UE_DECLARE_GAMEPLAY_TAG_EXTERN(Enemy_Status_Debuff_Taunted);
```

정의부에서는 실제 문자열 경로를 지정한다.

```cpp
UE_DEFINE_GAMEPLAY_TAG(
    Enemy_Status_Buff_WaveBuff,
    "Enemy.Status.Buff.WaveBuff"
);

UE_DEFINE_GAMEPLAY_TAG(
    Enemy_Status_Buff_RangedResistance,
    "Enemy.Status.Buff.RangedResistance"
);

UE_DEFINE_GAMEPLAY_TAG(
    Enemy_Status_Buff_MeleeResistance,
    "Enemy.Status.Buff.MeleeResistance"
);
```

태그를 사용하면 상태가 여러 시스템을 건널 때 의미가 유지된다. 예를 들어 C++에서는 적이 어떤 태그를 가지고 있는지 확인하고, GAS Effect에서는 해당 태그에 따라 적용 여부나 계산식을 바꿀 수 있으며, UI에서는 태그 변화 이벤트를 받아 상태 표시를 갱신할 수 있다.

## 7. 웨이브 버프와 난이도 조정

`feat: enemy wave buff` 이후에는 웨이브 자체가 적을 강화하는 방향으로 확장되었다. 여기서 중요한 점은 버프가 단순 수치 변경이 아니라 "언제, 어떤 적에게, 어떤 상태로 적용되는가"의 문제라는 점이었다.

웨이브 후반 밸런스 작업에서는 세 가지 축을 함께 봐야 했다.

1. 적의 기본 능력치: 체력, 이동 속도, 공격력, 샤드 드롭량
2. 웨이브 데이터: 등장 타이밍, 수량, 적 타입 조합
3. 플레이어 방어력: 터렛 소환 제한, 터렛 시너지, 보상 곡선

따라서 `update: balancing dt cahnges`, `update: stage 3 wave update`, `update: enemies buffed` 같은 커밋은 단순 데이터 수정이 아니라 웨이브 시스템의 체감 난이도를 맞추는 작업이었다.

## 8. 후기

이 시기의 작업은 적 AI를 "움직이는 Actor"에서 "상태를 가진 게임플레이 유닛"으로 확장한 과정이었다. Behavior Tree는 의사결정을 담당하고, Blackboard는 현재 AI 상태를 공유하며, Gameplay Tag는 GAS와 UI까지 이어지는 상태 언어가 되었다.

특히 도발과 웨이브 버프는 서로 다른 성격의 기능이지만, 둘 다 상태 복구와 상태 표현이 중요했다. 도발은 시간이 끝난 뒤 원래 목표로 돌아와야 하고, 웨이브 버프는 어떤 적에게 어떤 강화가 적용되었는지 명확히 남아야 한다. 이 두 작업을 통해 SOW의 적 AI가 더 게임다운 반응을 하게 되었다.
