# [SuraS 개발일지 5] Level Sequence, Arena Lock, 패키징과 후반 안정화

## 1. 개요

### 1.1 사전 배경

적 AI의 기본 이동과 공격 패턴이 만들어진 뒤에는 이를 실제 레벨 흐름에 연결해야 했다. 적이 잘 움직이고 공격하더라도, 게임 안에서 언제 등장하고 언제 전투가 시작되며 언제 전투가 끝나는지가 정리되지 않으면 하나의 완성된 경험이 되기 어렵다.

후반 작업에서는 적 AI를 Level Sequence, Trigger Box, Arena Lock, 영상 재생, 패키징 안정화와 연결했다. 이 시기에는 코드 자체보다도 "에디터에서는 되는데 패키징하면 안 되는 문제", "레벨 전환 중 플레이어 조작이 들어가는 문제", "시네마틱이 끝난 뒤 AI 상태가 복구되지 않는 문제" 같은 제작 후반부의 문제를 많이 다루었다.

### 1.2 수행 요약

이번 단계에서 다룬 주요 작업은 다음과 같다.

1. Level Sequence 기반 적 등장 연출
2. Level Sequence 중 AI Controller 정지/재시작
3. Arena Lock과 전투 구역 제어
4. 적 사망 연출과 dissolve effect
5. 레벨 전환 영상과 인트로 영상 파이프라인
6. Cook/Package 오류 수정
7. 최종 적 공격 판정 안정화

## 3. Level Sequence와 적 AI

UE의 Level Sequence는 연출에는 편하지만, AI와 함께 사용할 때는 상태 관리가 까다롭다. 시퀀스 중에는 적이 연출용으로 움직이거나 Spawnable로 등장할 수 있고, 그동안 Behavior Tree가 평소처럼 작동하면 연출과 AI가 서로 충돌한다.

그래서 `ASuraCharacterEnemyBase`에는 AI Controller를 끄고 켜는 함수가 추가되었다.

```cpp
void ASuraCharacterEnemyBase::TurnOffAIController(bool bIsLSSpawned)
{
    GetAIController()->EndPursueState();
    GetAIController()->GetBrainComponent()->StopLogic("Turn Off AIC");

    if (bIsLSSpawned)
    {
        bIsLevelSequenceSpawned = true;
        GetDamageSystemComp()->OnDeath.RemoveAll(this);
    }
}
```

여기서 `EndPursueState`를 먼저 호출하는 것이 중요했다. 시퀀스에 들어가기 전에 Pursue Token을 반환하지 않으면, 이후 일반 전투로 돌아왔을 때 플레이어 주변 추격 슬롯이 이미 사용 중인 것처럼 남을 수 있다.

다시 전투로 돌아올 때는 AI 로직을 재시작한다.

```cpp
void ASuraCharacterEnemyBase::TurnOnAIController()
{
    if (bIsLevelSequenceSpawned && GetDamageSystemComp()->GetIsDead())
    {
        OnDeathTriggered();
        return;
    }

    bIsLevelSequenceSpawned = false;
    GetDamageSystemComp()->OnDeath.AddUObject(this, &ASuraCharacterEnemyBase::OnDeathTriggered);

    UAnimInstance* const EnemyAnimInstance = GetMesh()->GetAnimInstance();
    EnemyAnimInstance->StopAllMontages(true);

    GetAIController()->GetBrainComponent()->RestartLogic();
}
```

시퀀스 중 죽은 적은 바로 일반 사망 처리로 넘어가지 않게 하고, 시퀀스가 끝난 뒤 사망 처리를 이어가도록 했다. 이런 처리가 없으면 연출 중 사망한 적이 destroy되며 Sequencer reference가 꼬이거나, 반대로 죽은 적이 다시 AI를 켜는 문제가 생길 수 있었다.

## 4. 적 사망 처리와 dissolve

적이 죽을 때는 단순 Destroy가 아니라 dissolve, 사망 애니메이션, Kill Log, 사운드가 함께 실행되도록 했다.

```cpp
void ASuraCharacterEnemyBase::OnDeathTriggered()
{
    UpdateHealthBarValue();

    DissolveTimeline->PlayFromStart();

    float DeathAnimDuration = 3.f;

    if (!DeathAnimations.IsEmpty())
    {
        UAnimMontage* DeathAnimation = GetRandomAnimationMontage(DeathAnimations);
        PlayAnimMontage(DeathAnimation);
        DeathAnimDuration = DeathAnimation->GetPlayLength();
    }

    if (AIController->GetCurrentState() == EEnemyStates::Pursue ||
        AIController->GetCurrentState() == EEnemyStates::Attacking)
    {
        AIController->EndPursueState();
    }

    AIController->ClearFocus(EAIFocusPriority::Gameplay);
    AIController->GetBrainComponent()->StopLogic("Death");
}
```

사망 시에도 Pursue Token을 반환하는 이유는 전투 중 적이 죽었을 때 다른 적이 그 자리를 이어받을 수 있어야 하기 때문이다. 만약 사망한 적이 토큰을 들고 사라지면 남은 적들은 계속 Chase 상태에 머무를 수 있다.

## 5. Arena Lock

후반에는 `ArenaLock`을 추가했다. FPS 전투에서는 특정 구역에 들어갔을 때 문이 닫히고, 적을 모두 처치하면 다시 열리는 구조가 자주 필요하다. SuraS에서도 적 Trigger, Spawn, Level Sequence와 함께 Arena Lock을 사용해 전투 구역을 제어했다.

Arena Lock 작업은 단순 문 잠금이 아니라 전투 연출과 AI 시작 타이밍을 맞추기 위한 장치였다. 적이 스폰되기 전부터 플레이어가 구역을 빠져나가면 전투가 성립하지 않고, 반대로 전투가 끝났는데 문이 열리지 않으면 진행이 막히기 때문이다.

## 6. 영상 파이프라인

11월에는 레벨 전환 영상과 인트로 영상 작업도 진행했다. 단순히 mp4 파일을 넣는 것이 아니라, UE의 Media Player, Media Texture, Material, Widget을 연결해야 했다.

작업 흐름은 다음과 같았다.

1. `Content/Movies`에 영상 파일 추가
2. Level Intro, Level Transition용 Media Player 생성
3. 영상 재생용 Widget 제작
4. 레벨 전환 Trigger와 Widget 연결
5. 로딩/인트로 중 플레이어 조작 제한
6. 인트로 스킵 기능 추가

이 과정에서 `fix: intro movie loading logic`, `fix: separte level intro pipeline`, `fix: no more player control via direct approach`, `feat: skip intros` 같은 커밋들이 이어졌다. 기능 자체보다도 레벨 로딩, 저장 데이터, 플레이어 입력과 얽힌 예외 처리가 많았다.

## 7. Cook과 Package 오류

UE 프로젝트 후반에서 가장 현실적인 작업은 패키징 오류 수정이었다. 에디터에서 잘 실행되는 프로젝트라도 Cook 단계에서 asset reference, plugin binary, public header include, config 문제가 발생할 수 있다.

`102d94e2d`와 `aaef6308b` 커밋에서는 Cook/Package 오류를 정리했다. 특히 UE는 `.uasset` 경로와 참조가 깨졌을 때 에디터에서는 늦게 발견되거나 로컬 캐시 덕분에 통과하는 경우가 있어, 패키징 단계에서야 문제가 드러나기도 한다.

개발자로서는 화려한 기능 구현보다 지루한 단계지만, 포트폴리오 관점에서는 오히려 중요한 경험이다. 실제 게임 개발은 "기능을 만들었다"에서 끝나지 않고 "빌드 가능한 상태로 유지했다"까지 포함하기 때문이다.

## 8. 최종 적 공격 안정화

마지막 선택 커밋인 `4c012d909`에서는 원거리 적 투사체와 Charger 공격을 Static Mesh 기반으로 수정했다. 개발 후반에도 적 공격 판정과 표현은 계속 조정되었다.

특히 원거리 적과 Charger는 플레이어에게 직접적인 위협을 주는 적 타입이기 때문에, 투사체가 보이는 방식과 충돌 판정이 명확해야 했다. 아무리 AI 상태 전환이 잘 되어도 공격이 읽히지 않으면 플레이어는 불합리하게 맞았다고 느끼게 된다.

## 9. 후기

후반 작업을 하며 느낀 점은 게임 개발에서 AI는 독립적인 시스템이 아니라는 것이다. 적 AI는 Level Sequence, Arena Lock, UI, 사운드, 영상, 저장 데이터, 패키징과 모두 연결된다. 특히 SuraS처럼 적 행동이 전투 연출의 핵심인 프로젝트에서는 AI 상태를 언제 멈추고 언제 다시 켜는지가 매우 중요했다.

이번 SuraS 개발일지 시리즈를 정리하며 본인이 맡은 작업을 다시 보면, 단순히 "적을 만들었다"기보다 적을 중심으로 전투 흐름을 구성했다고 보는 편이 맞다. 데미지 시스템, Behavior Tree, 추격 토큰, 벽 타기, 협동 공격, Charger, Turret, Level Sequence 연동까지 이어지며 SuraS의 전투 경험을 만드는 데 기여했다.
